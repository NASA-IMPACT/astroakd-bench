# AstroAKD-Bench 0.6.7 — Scorable one-value experiments with GPT-5.2

## Why a new candidate set?

The 50 tasks from 0.6.5 (32 archive, 10 coordinate, 8 literature) were useful as science-driven prompts but were not necessarily answerable by a single archive response. The 0.6.6.1 report had no approved gold answers; a `completed` run was **not** a correct answer. Rather than invent truth with an LLM, 0.6.7 derives **new, narrower questions** from the 42 successfully collected MCP reference responses.

Each scorable question names an archive and an observable record key (SIMBAD object name, MAST obsid, HEASARC catalog + obsid, Gaia DR3 source_id, or VizieR catalog + Source/2MASS identifier). It asks for exactly **one field**, with a numeric unit/tolerance where relevant. The 50 tasks are 42 first-field questions plus eight second-field questions from the same real reference dataset. This deliberately **does not** retain the former 32/10/8 distribution: eight truly literature-driven tasks need separate ADS/bibcode scientific validation before they can be scored objectively. Do not describe these new 50 as ADS-generated.

Answer keys are fixed from **previously observed MCP table rows**, with reference-file digest, source task ID, row index and identifier. They are not generated by GPT-5.2, and agent outputs never influence them. They are `reference_anchored_unreviewed` rather than independently certified scientific truth.

## Step 1 — Build 50 synthetic *scorable* questions from your references

Run this in the AstroAKD-Bench repository. It requires no OpenAI key or live MCP connection:

```bash
uv run python -m benchmark build-scorable \
  --source-tasks datasets/generated/gold_mixed_065_single_call_42.jsonl \
  --references datasets/validated/gold_mixed_065_ref_42.jsonl \
  --count 50 \
  --tasks-output datasets/generated/scorable_50.jsonl \
  --oracle-output datasets/gold/scorable_50_reference_oracle.jsonl \
  --answers-csv datasets/gold/scorable_50_question_answers.csv \
  --report datasets/gold/scorable_50_report.json \
  --json-format pretty
```

These output filenames are separate from all existing 0.6.5/0.6.6 data. The CSV shows each question alongside its exact reference answer, unit and tolerance, **for reviewers only**. **Never** pass the answer CSV, oracle JSONL or previous reference journal to the model runner.

## Step 2 — Three-arm pilot with GPT-5.2

`OPENAI_API_KEY` must be set, and the standalone Astroquery MCP service must be running for arms A and B. `API_DEV_KEY` is needed only by the MCP server for authenticated ADS, but the new one-value dataset does not require ADS. The three modes are:

- A `mcp_only`: Astroquery MCP functions, minimal safe tool prompt, **without** `AstroAKD_Instruction.md`.
- B `mcp_instruction`: same MCP functions plus the **AstroAKD agent** instruction (`docs/agent/AstroAKD_Instruction.md`), not the benchmark's question-generation instructions.
- C `web_only`: OpenAI hosted `web_search` and no MCP.

```bash
uv run --with openai python -m benchmark run-three-arm \
  --tasks datasets/generated/scorable_50.jsonl \
  --agent-instruction docs/agent/AstroAKD_Instruction.md \
  --model gpt-5.2 \
  --limit 5 \
  --max-turns 8 \
  --max-calls 12 \
  --max-tool-bytes 262144 \
  --task-timeout 900 \
  --output datasets/agent/scorable_50_gpt52_runs.jsonl \
  --report datasets/agent/scorable_50_gpt52_report.json
```

The experiment uses the same model and task order in all three arms. GPT-5.2 Structured Outputs schemas are requested for both tool-using Chat Completions and hosted web-search Responses. This raises format compliance, but API/model compatibility must still be confirmed with a real laptop pilot. No gold data is sent to the agent. For the full experiment, run the **same command with `--resume` instead of `--limit 5`**, retaining all other resource settings.

## Step 3 — Score each arm and preserve every actual answer

After the pilot or complete run, score the append-only progress journal:

```bash
uv run python -m benchmark score-scorable \
  --tasks datasets/generated/scorable_50.jsonl \
  --oracle datasets/gold/scorable_50_reference_oracle.jsonl \
  --runs datasets/agent/scorable_50_gpt52_runs.jsonl.progress.jsonl \
  --comparison-csv datasets/reports/scorable_50_gpt52_ABC_answers.csv \
  --summary-csv datasets/reports/scorable_50_gpt52_rates.csv \
  --report datasets/reports/scorable_50_gpt52_scores.json \
  --json-format pretty
```

The **50-row comparison CSV** has each question, its reference snapshot answer, and all three arm answers **regardless of correctness**. Incorrect JSON, abstentions, run errors and not-run states remain visible. The summary computes per-arm `reference_match_pct_attempted` = CORRECT / attempted × 100 and `reference_match_pct_all_questions` = CORRECT / 50 × 100. Unstructured answers count as an incorrect *strict-format match*, **not as a factual claim about the astronomy**. Check `incorrect_format` separately. A pilot with five attempted questions should never be displayed as full 50-question coverage.

## Scientific-integrity and reproducibility rules

1. `reference_anchored_unreviewed` **does not equal** `verified` gold. Report these as *snapshot-reference match rates*, never scientifically verified success percentages. Full scientific verification still requires independent source review by a domain expert.
2. Identity and answer are separate: an ObsID, Gaia source_id or catalog source key is embedded in the question; the requested property is withheld from every arm until scored.
3. The original 50 mixed questions and all 42 real reference responses remain immutable. Source and new dataset SHA-256 values must be retained alongside experimental reports.
4. A 42-result reference snapshot can generate 50 distinct field-level questions, but it **does not** represent 50 independent archive queries or 50 independent astronomical objects. The report records archive composition and provenance.
5. Literature-driven answerable questions should be added only when the exact ADS paper, bibcode, associated archive observation ID or object mapping has been independently verified; 0.6.7 is deliberately a narrower pilot.
6. This release is offline-qualified only. No GPT-5.2 API calls were issued from this build environment.
